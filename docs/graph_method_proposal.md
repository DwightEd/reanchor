# 回看节点、证据选择与约束归属

更新：2026-09-11。本文是当前研究要求，取代此前的 G0/G1 训练方案。
历史方案保存在 Git 和带日期的笔记中，不作为当前实现说明。

## 研究目标

在真实自回归生成中，先定位模型重新读取、选择证据信息的**回看节点**，
再检查这些节点附近，来源内容与当前回答的对象、动作、限制条件如何组合。
目标是找到可复现的错误绑定模式，最终用于无幻觉标签训练的错误定位。

回看节点是计算事件，不是幻觉 token 标签。正确回答和错误回答都可能出现。
“定位决策窗口”与本研究的“定位回看节点”指同一目标，不另造概念。
不预先指定实体才能运行节点定位；具体实体/词语只用于事后解释和实例核验。
本轮先做缓存测量与对照，不训练检测器，不把 attention 的变化直接称为因果影响。

## 已确认的控制要求

原始预测为 z_t = LM(prompt, y_<t)，原模型概率为 softmax(z_t)。
logits 来自最终残差表示、归一化及词表投影，包含 attention、MLP 等计算的共同作用。
单条 attention 边不能解释全部 logit 变化。

当前 sampling.py 在 eval 模式前向：先得到原始 z，再用 softmax(z / temperature)
和 top-p 抽样；seed 只传给抽样用的 torch.Generator。
保存的 top_logits、chosen_logit、log_normalizer、logit_entropy 都属于未施加温度的 z。
float32 保存不代表前向是 float32；这批前向为 bfloat16。

- 固定模型、精度、前缀、位置和执行方式时，改变抽样 seed/温度不应直接改变当前原始 logits。
  用相同前缀实测数值误差，不能承诺跨设备/算子逐位一致。
- seed/温度会改变实际选择，进而改变后续前缀和原始 logits。相同 seed 不等于相同前缀。
- 同一前缀的首次不同输出，仍由同一个预测状态抽样得到；在这一步不能用前状态区分两条未来。
- 本轮固定已有 token ID 与采样缓存，仅导出原始概率；不重新采样、不把温度后分布当模型不确定性。
- 自动检查同一采样批次中跨 seed 的相同前缀：比较原始 top 候选、其 logits 与 log-normalizer。
  这只是已保存量的一致性检查，不等于比较了完整词表或所有激活。
- 同一回答中对齐语法结构/相同 token 的正确与错误段落，只是观察性对照，前缀仍不同。
  不能宣称已消除难度、位置、词形、模板、上下文长度等全部混杂。
- 后续需要补中间状态时，在固定 token 序列上做前向；不重新生成。
  对齐 KV-cache、dtype、attention 实现，先测重复前向误差，再解释条件差异。

top2_margin = z(top1) - z(top2)；chosen_margin 是实际 token 相对最强其他候选的差。
抽样 token 不一定是 top-1，chosen_margin 可以为负。top-5 概率使用完整词表 log-normalizer，
不能对 top-5 再 softmax。旧缓存没有完整 logits 熵时留空，不从 top-5 冒充恢复。

## Attention 熵与 head 选择

对每个 layer/head 单独在固定 passage token 集合 S 上归一化：

    p_t(j) = A_t(j) / sum_{k in S} A_t(k)
    H_t = -sum_j p_t(j) log2 p_t(j)

熵较高表示该分布更分散；不严格等于没有任何突出峰。多个 token 还可能属于同一证据片段，
因此 token 熵高也不自动等于存在多个互相竞争的语义来源。
H 只在同一来源集合、同一 head 和适当的前缀/词形对照下解释；原始 source 总量为零时无定义。
归一化会放大很小的权重，原始边权必须保留。

“正确和错误回看节点都比顺序输出更分散，而错误更甚”是待检验假设，尚非总体结论。
例如 L24/H27 在数字前空格：正确 1.53 bits、错误 4.43 bits；但错误的 12 处已降至 0.65 bits。
必须检查组织阶段到内容输出的过程，不能只对比被输出的实体。
head 间分歧也可能是合理分工；不能要求所有 heads 读取相同位置。

过去展示的 L24/H27、L15/H30 是根据实例中可读的强边事后挑出的说明性 heads，
不是已证实的检索/推理 head，也没有证明它们代表全模型或对错误有因果作用。
仅凭一个 token 的高 attention 不能确定 head 的功能，head 编号也没有先后功能含义。

本轮所有指定位置导出全部 layer/head，包括低权重、零权重和非最大边。
今后筛选功能 heads 时，使用独立的、不含幻觉标签的参考样本，考察来源读取变化及跨实例稳定性；
先固定 head 集合再检验正确/错误差异。同时保留所有 heads 的结果，检查选择偏差。
中间层和后部层是检查重点，不是预先排除其他层的理由。

## 节点量化与图建模：待验证的定义

现有 shift 是相邻 attention 分布的 TV 距离。它会把沿原文相邻 token 的顺序读取算成大变化，
只保留作对照，不以其峰值直接定义回看或错误。

下一步节点量化使用两个可解释的方面，不先拼成一个错误分数：

1. **读取位置迁移**：在 source token 邻接图上度量分布迁移。相同词的分词移动成本低，
   沿邻词顺序读取成本低，跨远处片段成本高；运输距离使用实际来源位置，不只比较熵。
2. **局部读取集中**：比较一个连续 source 邻域的原始 attention 总量在当前与此前窗口的变化。
   邻域由原文位置/词边界定义，不由已知实体或幻觉标签定义。

先逐 head 识别相较自身过去窗口异常的迁移或集中变化，组成回看候选窗口。
允许“尚未收敛的寻找”与“集中选定来源”两种过程；不能只留下低熵、已经选定的位置。
邻域宽度、历史窗口及候选门槛需要在独立参考样本固定，不能在这四例上调到符合预期。
连续读取、子词、标点、正常条目转换都要纳入对照。检测不使用未来；事后窗口图可以看后续。
上述图距离/事件提取尚未实现，本轮不把提出的公式写成已验证算法。

图中的回看节点需要保留 source、生成历史、当前 query 的真实 token 身份与 layer/head。
检查“当前对象/动作指向的来源”和“属性/时长指向的来源”是否保留了适用关系。
source 邻接本身不能判断语义归属；存在路径、复制成功、多个 heads 一致均不等于事实正确。
attention 路径乘积也只是读取代理，不能忽略 MLP、value、残差与归一化后声称得到完整因果流。

## 本轮实现范围与验收

执行路径：main.py decisions -> DecisionInspection.run() -> 具体 CSV。
保持现有采样与 routes 算法，先完成已同意的两个检查，并增加相同前缀的数值审计。

- 读取指定实例的固定预测窗口，核对窗口的实际 token 文本，防止误用另一批生成的编号。
- 导出每个保存的 top 候选的 ID、文本、原始 logit、完整词表概率，以及实际选择概率/margin。
- 对指定 prompt key 和生成历史 key，导出所有层、所有 heads 的真实边权与前一步权重。
  新出现的 key 没有可比前值时留空；不可见的 key 不导出。query 自身的 distance=0，不叫回看。
- t 行 query=P+t-1，预测 response token t。若追踪 response token u 自身的读取，
  对应的是行 u+1，而不是预测它的行 u；本轮不把两者混用，也不把文本邻接冒充神经路径。
- 自动导出批次内相同前缀的原始候选数值差异；不能用不同实际抽样 token 的 chosen_logit 差异
  误报同一预测状态不一致。相同前缀记录是重复测量，不是独立统计样本。
- 脚本只用现有 NPZ，在 CPU 运行，有进度条；保存数字和输入依据，不生成 report，不改原始采样。

验证通过项目公共入口 main.py 的 CSV 输出进行：原始概率不受温度缩放、抽样 token 可非 top-1、
前后时序与新 key 可见性正确、低权重非最大边仍导出、相同前缀只比较相同预测任务。
使用微型真实 Llama 前向检查不同 seed/温度对同一前缀的原始状态不产生直接影响。
合成测试用于程序正确性，不作为机制实验结果。

当前本地只有四例派生 CSV，完整 NPZ 在服务器。本轮可完成代码和程序验证；
真实 top-5 与历史边需要服务器运行后同步，不能在本地编造或从旧 CSV 反推。

## 证据成立的顺序

1. 先验证测量与采样控制，再确认回看节点相较顺序输出的差异。
2. 在回看窗口内部对照正确/错误的来源选择和约束归属；不预设错误一定更高熵。
3. 有稳定结果后，在独立 source 上冻结算法评估；新生成回答需要自己的错误标注。
4. 最后用有限、固定前缀的干预检查机制，不能用观察相关性替代因果结论。
